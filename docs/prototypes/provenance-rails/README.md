# Provenance Rails prototype

The server half of the OCR-correction editor prototyped in [`../tiptap-provenance`](../tiptap-provenance). The pipeline is:

1. OCR output comes in.
2. People edit it with provenance tracking.
3. Saves are validated.
4. Saves are indexed for citation and provenance search.
5. Documents are read as clean HTML and printed as PDF through Typst.

This is a research artifact in the Lexxy fork; it doesn't use Lexxy or Action Text.

## Run it

```sh
bin/rails db:prepare              # creates the SQLite database and imports the sample (test/fixtures/files/romans_pages.json)
(cd ../tiptap-provenance && npm install && npm run build:rails)   # builds public/editor/editor.js
bin/rails server
```

PDFs need the [Typst CLI](https://github.com/typst/typst/releases) on `PATH`, or set `TYPST=/path/to/typst`.

Tests:

```sh
bin/rails test                                             # 24 model and integration tests
(cd ../tiptap-provenance && npm run test:rails)            # browser round trip: edit → save → read → trace → search → PDF
(cd ../tiptap-provenance && node scripts/contract_fixture.js)  # regenerates the JS↔Ruby stand-off contract
```

## Data model

| Table | What it holds |
|-------|---------------|
| `documents` | `body`: the editor's ProseMirror JSON, the canonical copy, with a `schema_version`. `plain_text` is derived on save for text search. |
| `ocr_runs` | One engine's pass over one page: `text`, plus `glyphs` (one per character) with word, confidence and bounding box. |
| `provenance_spans` | Derived from the body: one row per run of same-origin text (block, UTF-16 offsets, origin, run, by, session). |
| `citations` | Derived from the body: one row per `bibleRef` mark, with the OSIS reference as an integer verse range (`book × 10⁶ + chapter × 10³ + verse`). |
| `correction_events` | Every insertion and deletion the editor reports, with what it replaced. Always attributed to the session user, never the client payload. |

`provenance_spans` and `citations` are rebuilt from the body on every save (`Document::Indexable`), so they can't drift from the text.

## The pieces

- **`Document::Body`** (`app/models/document/body.rb`) does three jobs:
  - It validates the untrusted editor JSON against an allowlist of nodes, marks and attributes. It also checks provenance origins, OSIS references and link schemes.
  - It flattens the body into textblocks with stand-off mark ranges.
  - It computes offsets in **UTF-16 code units**, like the editor. A contract test (`test/models/document/body_test.rb`) checks it against output generated by the editor's own `toStandoff`, including emoji and characters outside the Basic Multilingual Plane.
- **`OcrImport`** turns engine output into `OcrRun`s and a body. Each word's confidence and box go onto its characters' glyphs, and `CitationDetector` turns references like "Romans 8:29-30" into `bibleRef` marks.
  - Input: `POST /ocr_imports` with a bearer token from `OCR_IMPORT_TOKEN`.
  - Format: `{ title, pages: [ { page, engine, engine_version, paragraphs: [ [ { text, conf, bbox } ] ] } ] }`.
- **`Document::Traceable#origin_at(block_index:, offset:)`** answers "where did this character come from?" A human character returns who typed it in which session. An OCR character returns its glyph (engine, version, page, confidence, bounding box).
  - Humans can only delete OCR characters, never insert into a run. So a run's surviving text is a subsequence of the original, and `OcrRun#glyph_at` recovers glyph indexes by matching it back.
  - The only ambiguity is which of two identical adjacent characters was deleted.
  - Endpoint: `GET /documents/:id/provenance.json?block=&offset=`.
- **`Citation.overlapping("Rom.8")`** is a range-overlap query on verse ids. It accepts a verse, a range (`Rom.8.28-Rom.8.30` or `Rom.8.28-8.30`), a chapter or a book. UI: `/citations?ref=Rom.8`.
- **`Document::ReadingHtml`** renders the reading page with every mark except provenance; citations become `<cite data-osis>`.
- **`Document::TypstSource`** plus `app/views/documents/print.typ.erb` produce the print source: a 6 × 9 in page with mirrored margins and the Libertinus Serif font that Typst embeds.
  - Every run of text is emitted as a Typst string literal, so nothing a reader typed is interpreted as markup (tested with hostile input).
  - `bibleref(osis, body)` in the template is where citation styling lives.
  - Output: `GET /documents/:id.typ` and `GET /documents/:id.pdf` (PDF/A-2b).

## Known gaps

- **PDF/X.** Print-on-demand vendors (IngramSpark, KDP) generally ask for PDF/X, and Typst 0.15 only produces PDF/A and PDF/UA. Either add a conversion step (typically Ghostscript) once you have the vendor's spec, or move typesetting to LaTeX/ConTeXt or Prince.
- **Auth.** The session holds a name typed into a form, as a stand-in for real authentication. OCR imports use a shared token.
- **Search.** Text search is `LIKE`. Use SQLite FTS5 or Postgres full-text search for real corpora. The citation detector is intentionally small (English names, `chapter:verse` forms); use a full reference parser for real text.
- **Trusting the client.** Human marks carry `by`/`session` from the editor, but the event log uses the server's user. A stricter version would reject human spans whose `by` doesn't match the saving user, for spans that are new in this save.
- **Reindexing cost.** Every save rebuilds that document's index rows. That's fine for chapter-sized documents; diff them for book-sized ones.
- **Schema drift.** The server validates against its own allowlist. When the editor schema changes, bump `schema_version` and update `Document::Body::NODES`/`MARKS` and the contract fixture together.
